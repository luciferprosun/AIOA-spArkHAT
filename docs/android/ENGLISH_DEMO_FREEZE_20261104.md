Scope: owner-supplied final demo/English pass, 4 November 2026.

## Minimal change

- Android uses its existing English resources with per-app locale `en-US`. No new APK, package, signer, versionCode, Keystore or enrollment is required for this language change. The saved trusted-host preferences were hashed before and after and matched.
- Linux changes only human-facing text in `web/index.html`, `web/mobile_devices_dom.js` and `web/mobile_chat.js`.
- `runtime/mobile_gateway/operator_chat.py` changes only the human-readable native financial-dialog text. Its Python structure, private transport, exact review packet, policy, cost bound and approval behavior remain unchanged.
- Existing DOM/browser regression assertions are updated for the English labels, preserving all state, revocation, pending-session, credential-isolation and button assertions.

The HTML tag structure, routes, IDs, resource URLs, capabilities and controls remain unchanged. The page language changes from Polish to English. No new frontend, worker, backend, provider, Core, journal, approval store or framework is introduced.

## Qualification and rollout

Do not deploy an unqualified working tree. Freeze the actual source SHA, preserve required checks and qualify the changed Native source. Keep the already installed 401 APK unchanged: its source and signature remain independently identified, and the existing signed source-upgrade/reconnect path supplies fresh host binding.

A new APK would require a higher versionCode, the same signer, exact-source CI and an in-place update. That path is unnecessary while existing English Android resources suffice. Do not manufacture an APK update merely to translate the Linux console.

Preserve the already accepted Native checkout as rollback evidence. Deploy the qualified host from an isolated checkout of the same repository, using the same private state/TLS/host identity. Verify the actual old process PID/start/UID/argv/cwd/listener before sending SIGINT, and obtain authentic PolicyKit authorization before stopping it. Never run a second Core listener. A lease expiry is a real reason for authenticated renewal; mere passage of the audit is not.

Do not restore old databases, counters, warrants, revocations or UNKNOWN. No uninstallation, clearing, downgrade, forced kill, Funnel or TLS bypass. Protected services remain untouched.

## Acceptance gates

- Installed 401 bytes/certificate and saved pairing remain unchanged.
- Fresh Native source/capsule and real owner admission are verified.
- Reconnect and signed status are actually read by the physical phone.
- English Android and real Linux UI are captured without private data or foreign overlays.
- Any new English Muse question receives its own exact local financial approval, at most USD 0.05 and one attempt. Historical usage does not authorize another call.
- Signed request/thread/result and actual UI readbacks agree. No fixture result is presented as LIVE.
- Native READ Worker remains NOT_READY unless a genuine existing Worker binding and tool receipt are available. Do not implement a Worker for the video.
- Final video exists, is playable, approximately 180 seconds, and shows actual English UI and an authentic English exchange; otherwise report exactly which clips/script are available.
- Portal fields and submission confirmation are separately verified; publication and submitting still require the owner's decision.

The private execution ledger, source qualification, physical evidence and final handoff record the actual outcomes. This document describes the bounded release path, not a claim that every later physical/video gate has already passed.

# NonZero W7A in the existing AIOA Core

Source: `luciferprosun/AIOA-NonZero-CloudOps-Agent`, commit
`392487849eddc7444f5159994b66b72e73f15934`. This is a selective W7A delta;
the earlier B5/B6 one-system retirement remains in force. The complete
69-module disposition is in `docs/provenance/NONZERO_W7A_MIGRATION.json`.

```text
Existing AgentRuntime / authenticated CLI and HTTP admission / STOP
  -> provider-neutral WorkerPort (untrusted CandidatePatch only)
  -> actual workspace observation / BoundedPatchSetPolicy
  -> fixed tests through the existing LinuxSandboxBroker
  -> finite repair coordinator (initial attempt + at most two repairs)
  -> independent source/tree verification
  -> ExecutionCapsule bound to the existing Core warrant
  -> existing CoreRemoteGitRoute
  -> independent readback / CoreIntentJournal / existing receipts
```

## Ownership and scope

Core admission, `CoreDualGovernor`, `CoreWarrantLedger`, `CoreIntentJournal`
and the existing transaction runner remain the authority and durability owners.
Worker events, model text, patch hashes and capsules do not grant permissions.
There is no second approval repository, effect repository, database, server,
provider manager or production `aioa_cloudops_agent` package.

The existing `RemoteGitPlan` demo restriction is preserved. A general verified
PatchSet is a separate typed proposal and must not bypass that production gate.
Any new local bare Git proof must pass through `CoreRemoteGitRoute` and bind
an exact base, feature branch, commit, consent and independent readback.
Real GitHub WRITE remains disabled until the current App, scoped consent and
UNKNOWN requirements are independently satisfied.

The optional Codex adapter must use the protocol generated by the installed
CLI, reject server-initiated approvals, correlate session/thread/turn identities,
bound output and deadlines, and own child cleanup. Protocol parsing alone does
not certify a model-driven coding workflow. No paid model request belongs to
offline qualification. A non-certified adapter fails closed.

Existing trusted sandbox preparation and release checks stay mandatory.
No Docker socket, image download, model-selected shell or fallback executor
is introduced. Tests and profiles are host-owned and content-bound.

## Evidence levels

Each component is reported separately as source present, implemented, wired,
tested, offline E2E, live verified and deployed. Historical PASS results are
not current qualification. Native deployment, production state migration and
repository retirement are outside this migration. The source repository and
all its references are preserved.

MIT attribution is already shipped verbatim in
`runtime/nonzero_cloudops/LICENSE-NONZERO.txt` (Copyright 2026 luciferprosun).
Adapted modules retain their exact W7A source paths and commit identity.

## Initial actual-tree profile

`runtime.mission.patchset` evaluates separate plain source/candidate exports,
with descriptor-confined reads and a fresh independent tree census. It allows
at most three changed files and 300 added/deleted lines, at most one deleted
file and 150 deleted lines, and requires a nonempty final tree. Input trees
are bounded to 256 files / 16 MiB, each file to 1 MiB and rendered diff to
256 KiB. Secret paths are refused before content reads. Tests, manifests,
Core authority/policy files and executable changes cannot be proposed.

`SourceIdentity` binds a host-selected export to the declared source commit;
it does not itself establish remote Git truth. The Core source reader and
publish route must independently bind that SHA and file preimages before
an approved effect. A PatchSet and its integrity hash remain non-authoritative.

## Offline implementation and deployment boundary

`repair` and `repair_validation` use a maximum of three attempts. The host
pins test scripts, counters, context and all workspace bytes. Each executed
stage uses the existing CoreToolRoute/LinuxSandboxBroker, independent
readback and canonical OPERATION/audit/outbox records. Applied certifies
report generation; PASS/FAIL is decoded separately. Uncertainty never
grants another repair attempt or an effect replay.

`patch_capsule` joins those records with the current source/tree/patch and
uses the existing Native Identity signer. Exact owner decisions use only
CoreWarrantLedger. PROJECT_PATCH_PROPOSAL_V1 has no registered executor.
`CoreRemoteGitRoute.prepare_patchset` prepares actual MODIFY postimages,
but the qualified remote profile still accepts only create-only demo plans.
General MODIFY/DELETE dispatch and the full coding-to-Git chain are blocked.

`coding_tasks` provides create_task/read_status/cancel/get_receipts through
an explicitly injected CoreCodingTasks on AgentRuntime. Its typed CLI parser
requires that admitted host binding; it does not bootstrap a new Core or add
a server. Signed intake receipts are stored in the existing transaction
repository. A canonical capsule can move a queued task to REVIEW_REQUIRED.
Cancel stops this pending intake; active Native effects still require the
existing operator STOP/revocation path. No deployed HTTP/UI switch is made.

The implemented intake exposes QUEUED/REVIEW_REQUIRED/CANCELLED. Remaining
state names are reserved contracts, not claims of an active end-to-end
controller. Deployment, arbitrary repository test profiles and production
model workers remain separate qualification gates. These features require
the existing `[native,nonzero]` extras; no new runtime dependency was added.

## Post-review qualification limits

The only certified test profile is `calculator-fixed-v1`: exact bundled AST
script bytes, three checks in each stage, and the workspace file set
`{calc.py}`. Other scripts/counts/IDs are refused before preparation. This
prevents candidate Python from sharing the trusted assertion frame through
an arbitrary exec-based profile. General application test execution needs a
separately qualified observer boundary and is unavailable in this release.

Diff work is bounded before matching and rendering: at most 2048 lines on
each side and 1,048,576 line-pair cells per changed file. The independent
census reopens every directory ancestry after descent. Host lifecycle guards
or immutable snapshots remain required for atomic use of an observation.

Capsule signing independently repeats semantic review after the actual-tree
recheck; a self-hashed loop/history is advisory metadata, not execution proof.
Fresh source IO occurs outside retryable transaction callbacks under the host
guard. Cancel/deadline is checked after test stages, session cleanup and final
producer cleanup before a successful result can be published.

VerifiedPatchSet reconstructs diff and line counts from bound pre/postimages.
Conversion to RemoteGitPlan is blocked for every new patch until a canonical
capsule-to-route join is separately qualified. Existing create-only Native
operations and their original route remain unchanged.

`392487849eddc7444f5159994b66b72e73f15934`. This is a selective W7A delta;

## Ownership and scope

Core admission, `CoreDualGovernor`, `CoreWarrantLedger`, `CoreIntentJournal`
and the existing transaction runner remain the authority and durability owners.
Worker events, model text, patch hashes and capsules do not grant permissions.
There is no second approval repository, effect repository, database, server,
provider manager or production `aioa_cloudops_agent` package.

The existing `RemoteGitPlan` demo restriction is preserved. A general verified
PatchSet is a separate typed proposal and must not bypass that production gate.
Any new local bare Git proof must pass through `CoreRemoteGitRoute` and bind
an exact base, feature branch, commit, consent and independent readback.
Real GitHub WRITE remains disabled until the current App, scoped consent and
UNKNOWN requirements are independently satisfied.

The optional Codex adapter must use the protocol generated by the installed
CLI, reject server-initiated approvals, correlate session/thread/turn identities,
bound output and deadlines, and own child cleanup. Protocol parsing alone does
not certify a model-driven coding workflow. No paid model request belongs to
offline qualification. A non-certified adapter fails closed.

Existing trusted sandbox preparation and release checks stay mandatory.
No Docker socket, image download, model-selected shell or fallback executor
is introduced. Tests and profiles are host-owned and content-bound.

## Evidence levels

Each component is reported separately as source present, implemented, wired,
tested, offline E2E, live verified and deployed. Historical PASS results are
not current qualification. Native deployment, production state migration and
repository retirement are outside this migration. The source repository and
all its references are preserved.

MIT attribution is already shipped verbatim in
`runtime/nonzero_cloudops/LICENSE-NONZERO.txt` (Copyright 2026 luciferprosun).
Adapted modules retain their exact W7A source paths and commit identity.

## Initial actual-tree profile

`runtime.mission.patchset` evaluates separate plain source/candidate exports,
with descriptor-confined reads and a fresh independent tree census. It allows
at most three changed files and 300 added/deleted lines, at most one deleted
file and 150 deleted lines, and requires a nonempty final tree. Input trees
are bounded to 256 files / 16 MiB, each file to 1 MiB and rendered diff to
256 KiB. Secret paths are refused before content reads. Tests, manifests,
Core authority/policy files and executable changes cannot be proposed.

`SourceIdentity` binds a host-selected export to the declared source commit;
it does not itself establish remote Git truth. The Core source reader and
publish route must independently bind that SHA and file preimages before
an approved effect. A PatchSet and its integrity hash remain non-authoritative.

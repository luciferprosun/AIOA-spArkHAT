# U09 synthetic Git and inert GitHub preview

`SyntheticGitPlan` produces immutable metadata, a commit/diff preview and an inert
GitHub PR/CI fixture. None grants authority or calls a service. It accepts only
a fresh `synthetic:` repository identity, revision 1, canonical one-line Python
value files and a `fixture/approved-*` branch. The source worktree is never a
product target; there is no remote, credential or general existing-repo adapter.

An independently supplied seed must match the exact repository, branch, revision
and immutable preimage. Git blob/tree/base/commit identities are predicted before
approval and verified using actual Git metadata and source readback after the
effect. SHA1 values are Git identifiers; SHA256 canonical operation/input/profile
bindings remain the authority and integrity contracts. Fixture authors, messages
and dates are fixed, and no production signing is used.

The operator pins the existing Git binary and reviewed PCRE2 dependency as
read-only U06 runtime resources. No host package installation is performed. This
extended runtime profile requires its own real U06 receipt. The immutable Core
operation still uses the accepted fixed Python argv; Python executes fixed Git
commands inside the U06 worker only. No legacy host bash execution is added.

The fixed worker creates a disposable `/work/repo`, ignores ambient Git config,
disables hooks/signing/helpers/maintenance/protocols and refuses foreign metadata,
links, dirty state, unapproved refs/config, or base/head drift before creating the
approved branch and commit. Exact actual status, diff, branches, log, head/tree
and source must match the reviewed plan before U06 artifact readback and native
completion. Replay and lost ACK use existing journal/liability reconciliation;
missing verified artifacts stay UNKNOWN without automatic execution retries.
This is a fresh single-writer fixture, not concurrent CAS for host repositories.
